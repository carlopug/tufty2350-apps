# Presentator dongle

BLE → USB keyboard bridge for the `apps/presentator` app on the Tufty 2350.

    Tufty 2350 (Presentator app)  --BLE, unencrypted GATT-->  ESP32-S3  --USB HID-->  PC

**Why it exists:** the official Tufty firmware (Pimoroni MicroPython `bw-1.28.0-3` + BTstack)
is built without BLE pairing support, so the badge cannot present itself to the PC as a
Bluetooth keyboard. With the dongle, the PC sees a standard USB keyboard: no drivers or
software to install, and the badge keeps the official, updatable firmware.

The link is unencrypted, so every message is authenticated instead (see [Protocol](#protocol-version-2)).

## Supported boards

| Board | Build and flash |
|---|---|
| ESP32-S3 Supermini (tested) | `pio run -e supermini -t upload` |
| Seeed XIAO ESP32S3 / XIAO ESP32S3 Sense | `pio run -e xiao -t upload` |

**First flash:**
1. Hold BOOT, plug in the USB cable, then release BOOT.
2. When the upload has finished, press RST (or re-plug the board). The board may stay in
   download mode and still show up as "USB JTAG/serial debug unit".
3. Once the firmware runs, the PC sees an HID keyboard called "Presentator Dongle" and a new
   serial (CDC) port.

Later uploads use the 1200-baud reset (see `platformio.ini`).

Tested on an ESP32-S3 Supermini (ESP32-S3FH4R2, 4 MB flash, 2 MB PSRAM) with Windows 10 and
PowerPoint.

**Slow builds in a synced folder?** If the project lives in Dropbox, OneDrive or a similar
folder, copy `platformio_local.example.ini` to `platformio_local.ini` (git-ignored) to build
outside it.

## Shared secret key (first time only)

The badge and the dongle share a secret key, which is never committed:

    python tools/genera_chiave.py

This creates two files:
- `src/chiave.h`, compiled into the dongle firmware;
- `apps/presentator/chiave.txt`, copied to the badge together with the app.

The build stops with a clear message if `chiave.h` is missing.

`--forza` generates a new key. After that, update **both** sides: re-flash the dongle and
copy the new `chiave.txt` to the badge. If the keys do not match, the badge shows
"Chiave diversa dal dongle" ("key differs from the dongle"). The dongle prints its key
fingerprint on the serial monitor at boot.

## Usage

1. Plug the dongle into the PC.
2. Start the Presentator app on the badge. The dongle connects by itself:
   - a blinking LED means it is searching for the badge;
   - a steady LED means it is connected;
   - the badge shows "Dongle pronto" ("dongle ready").
3. The dongle bonds with the first badge it finds. To bond it with another badge, hold BOOT on
   the dongle for 3 seconds.

The app has two modes, chosen from its main menu:

- **Gestisci presentazione** (run a presentation):
  - next and previous slide;
  - start (F5) or start from the current slide (Shift+F5);
  - end (Esc);
  - black screen;
  - hold A to go back to the menu.
- **Invia comandi** (send commands): entries read from `apps/presentator/comandi.json`. If that
  file is missing, the app uses `comandi.example.json`. An entry can be a website, a program,
  a text snippet, a keyboard shortcut or a small macro. The file format is documented at the
  top of `apps/presentator/comandi.py`.

Text is typed using an **Italian** keyboard layout. For another layout, adapt
`_layout_italiano()` in `apps/presentator/comandi.py`.

## Protocol (version 2)

The protocol is described in `apps/presentator/protocollo.py` and `src/proto_core.h`.

1. The badge translates every command into HID key presses.
2. It signs the command with HMAC-SHA256. The signature covers:
   - the shared key;
   - a random nonce that the dongle chooses for each connection;
   - an increasing counter.
3. It sends the command in chunks via GATT notifications.
4. The dongle drops forged, replayed or incomplete messages and replies with a status:
   in progress, done, cancelled or error.

Typing stops if:
- the badge cancels (A button);
- the Bluetooth link drops (HOME on the badge also drops it);
- the USB host suspends.

## Tests (no hardware needed)

    cd tools
    python -I test_badge.py                    # badge-side modules (CPython)
    python -I genera_vettori.py                # test vectors generated by the badge code
    g++ -std=c++17 -I../src test_proto.cpp ../src/proto_core.cpp -o test_proto && ./test_proto

App screens in the [try.badgewa.re](https://try.badgewa.re/) simulator. The harness uses
Playwright and a fake dongle, and saves one PNG per screen. It needs `chiave.txt`, so run
`genera_chiave.py` first.

    cd tools/simulatore
    PYTHONIOENCODING=utf-8 python prova_simulatore.py OUTPUT_DIR [ok|stati|json]

Debug log: USB CDC serial at 115200 baud (`pio device monitor`).
